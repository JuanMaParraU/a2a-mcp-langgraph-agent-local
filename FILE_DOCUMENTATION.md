## Project Overview

This project implements a fully local agentic AI system combining:

- **LangGraph** — for agent workflow orchestration (ReAct loop)
- **Ollama** — for serving local LLMs (Mistral, Gemma, etc.)
- **MCP (Model Context Protocol)** — for standardised tool access
- **A2A (Agent-to-Agent)** — for inter-agent communication over HTTP

The system runs entirely on-premises with no cloud API dependencies.

### `src/mcp_server.py`

| Attribute | Detail |
|-----------|--------|
| **Purpose** | MCP (Model Context Protocol) server that exposes research tools to agents |
| **Framework** | `FastMCP` from the `mcp` library |
| **Transport** | Streamable HTTP on port `8000` |
| **Tools exposed** | 3 tools (see below) |

**Tools:**

| Tool | Function | Description |
|------|----------|-------------|
| `duckduckgo_search(query)` | Web search | Uses the `DDGS` library to search DuckDuckGo, returns top 5 results with title, body, and source URL |
| `wikipedia_search(query)` | Encyclopedia lookup | Uses the `wikipedia` library to return a 3-sentence summary |
| `arxiv_search(query, max_results=5)` | Academic paper search | Uses the `arxiv` library to find papers sorted by submission date, returns title, authors, date, summary, and PDF link |

**Key implementation details:**
- All tools run blocking I/O in a thread pool via `loop.run_in_executor(None, ...)` to remain async-compatible
- Graceful shutdown via `signal` handlers (SIGINT, SIGTERM) and `atexit` cleanup
- Environment variables set: `NO_PROXY=127.0.0.1,localhost`, `PORT=8000`

| Attribute | Detail |

**Class: `langG_agent`**

| Method | Description |
|--------|-------------|
| `__init__()` | Initialises the Ollama model; tools and graph are lazily loaded |
| `_initialize()` | Async initialisation — fetches MCP tools and builds the LangGraph ReAct agent |
| `invoke(query, context_id)` | Single-shot invocation — sends query, waits for complete response |
| `stream(query, context_id)` | Token-by-token streaming — yields chunks as they arrive (LLM tokens, tool start/end events, errors) |
| `get_agent_response(config)` | Extracts structured response from graph state (`completed`, `input_required`, or `error`) |
| `_get_mcp_tools()` | Connects to MCP server via `MultiServerMCPClient` and retrieves available tools |

**Response format (Pydantic model):**
```python
class ResponseFormat(BaseModel):
    status: Literal["input_required", "completed", "error"]
    message: str
```

### `src/orchestrator/o3_agent.py`

| Attribute | Detail |
|-----------|--------|
| **Purpose** | Orchestrator agent — decides whether to answer directly or delegate to the research agent |
| **LLM** | `ChatOllama` with model `gemma3:1b` (lightweight for fast routing decisions) |
| **Graph type** | Custom `StateGraph` (not ReAct — uses explicit plan/delegate/synthesize nodes) |

**State schema (`OrchestratorState`):**
```python
class OrchestratorState(TypedDict):
    user_input: str
    plan: str | None
    needs_delegation: bool
    delegated_result: str | None
    final_response: str | None
```

**Graph nodes:**

| Node | Function | Description |
|------|----------|-------------|
| `plan` | `OrchestratorAgent.plan()` | Keyword-based routing — checks if input contains "research", "search", "wikipedia", or "paper" |
| `delegate` | `OrchestratorGraph.delegate()` | Sends the query to the research agent at `http://localhost:9991` via A2A protocol |
| `synthesize` | `OrchestratorAgent.synthesize()` | If delegated: wraps the result. If direct: invokes the LLM to answer |

**Graph flow:**
```
plan → [needs_delegation?]
         ├─ True  → delegate → synthesize → END
         └─ False → synthesize → END
```

**A2A delegation:**
- Uses `A2ACardResolver` to fetch the research agent's card
- Creates an A2A client via `ClientFactory`
- Sends the user message and streams the response
- Records inter-agent message metrics
